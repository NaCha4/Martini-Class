# 마티니 v2 구현 · 운영 안내

작성일: 2026-09-08

이 문서는 구현·배포 결과와 운영자가 입력할 실제 정보, 인수인계 작업을 설명한다. 회의록이나 동아리의 실제 결정 사항을 이 파일로 관리하는 것은 아니다. 실제 회의·안건·결정·후속 업무는 운영실에서 Firestore에 저장한다.

## 2. 임의로 정한 기본 운영 방식

- 일반 신청의 자격 확인 항목: 이름·학번·전체 전화번호. 공개 명부 검색은 제공하지 않는다.
- 대기자는 접수 순서대로 운영진이 승급을 제안한다. 제안 중인 좌석도 정원에 포함한다.
- 승급 제안의 기본 응답 시간은 6시간이며 행사 시작 이전으로 수정할 수 있다.
- 응답 기한이 지난 제안은 임원이 확인한 뒤 해제한다. 자동 알림·자동 배치는 없다.
- 행사 생성 초기값: 초안, 20명, 1주 뒤 일정, 전날 신청·자율 취소 마감. 실제 게시 전 수정한다.
- 무료 행사로 시작하며 유료 행사는 참가비·납부 안내를 입력해야 한다.
- 납부 확인·지출·환불 기록은 총무부 또는 회장단이 실제 거래 확인 후 입력한다.
- 노쇼에 자동 제재를 부과하지 않는다.
- 기록된 회비를 새 학기로 자동 승계하지 않는다.
- 휴동·탈퇴·졸업은 신청 자격을 즉시 중지한다. 기존 정산·신청 연결을 깨뜨리는 즉시 영구 삭제는 하지 않는다.
- 개봉 병 잔량을 늘리는 실사 정정은 일반 사용과 구분하고 사유를 남긴다.
- 잔량이 있는 재고의 관리 단위·병 규격은 변경할 수 없다.
- 결정에 연결된 회의 안건은 연결을 먼저 바꾼 뒤 제거한다.
- 확정 회의록의 정정은 회장단·운영 책임자만 가능하다.
- 공개 콘텐츠는 직접 공개 상태로 지정해야 홈페이지에 나온다.

## 4. 실제 데이터 저장 구조

- martini_v2_admins: 임원 권한과 임기.
- martini_v2_settings/club: 현재 학기와 운영 안내.
- martini_v2_members: 부원 명부.
- members/{id}/semesters: 학기별 활동 상태 이력.
- martini_v2_events: 행사, 정원, 등록·대기 수, 링크 해시.
- martini_v2_applications: 신청·납부·출석·확인 링크 해시.
- applications/{id}/history: 취소 후 재신청 이전 기록.
- martini_v2_inventory: 품목, 규격, 미개봉·일반 수량, 개봉 병 잔량.
- martini_v2_stockMoves: 재고 변경 전후 수치·사유·담당자·행사.
- martini_v2_finance: 확인한 입금·지출·환불.
- martini_v2_meetings: 회의와 안건.
- meetings/{id}/revisions: 회의록 수정 시점별 원문.
- martini_v2_decisions: 회의/안건에 연결된 결정·후속 업무.
- decisions/{id}/revisions: 결정 기록의 수정 버전.
- martini_v2_content: 공개 공지·활동 기록.
- martini_v2_audit: 중요 운영 변경과 내보내기 기록.
- martini_v2_rateLimits: 공개 요청 제한. 만료 필드의 TTL 적용은 별도 운영 승인 필요.

위 하위 컬렉션의 부모 이름에는 실제로 martini_v2_ 접두사가 포함된다. 설명에서만 축약했다.

## 5. 최신 구현·배포

- 배경과 로고를 public/assets로 이동하고 검정·금색 톤을 공개 화면, 신청, 운영실, 폼과 모달에 통일했다.
- 모바일 메뉴·운영 하단 메뉴·표 카드 전환을 제공한다.
- 회의 선택과 재고 이력은 오래된 기록도 조회하며, 연결 관계를 보존한다.
- 부원 등록과 실제 회계 장부를 분리하며 학기별 회비 장부의 중복 등록을 차단한다.
- 행사 취소 시 신청·대기·예약을 함께 종료하며, 출석 이력은 보존하고 추가 입금은 막는다.
- 대기 제안·수락 시 자격을 재확인하고 제안 거절은 일반 취소 마감과 분리한다.
- 학기말 개인정보 대상·미정산·건수·수정 여부를 검토하는 owner 전용 정리 화면을 제공한다.
- 대시보드와 재무 요약은 전체 기록을 불러와 계산한다.
- 서버·Firestore/Storage 규칙은 실제 Firebase 프로젝트에 적용했다. 기존 컬렉션은 이관하거나 지우지 않았다.
- 최초 운영자 계정·권한을 준비했고 비밀번호 설정 메일을 요청했다.
- App Check의 기존 Auth/Firestore/Storage 강제를 유지하고 실제 도메인에서 클라이언트 초기화를 활성화했다.

## 6. 운영자가 입력할 실제 정보

운영실에서 현재 학기, 활동 장소, 소개, 가입 오픈채팅 링크와 문의 채널을 입력한다. 가입 방법은 오픈채팅에서 안내한다. 회비는 실제 입금액을 장부에 기록하며, 설정에서 금액이나 기간을 정하지 않는다. 개인정보 페이지는 기존 GitHub 원문을 표시한다. 실제 명부와 재고는 가상 데이터로 채우지 않았다. 가입·회비 확인이 끝난 부원을 입력한 뒤 첫 행사를 모집한다.

초기 owner 임기는 2027-02-28 23:59:59 KST이다. 임기 전에 후임 운영자를 등록한다.

개인정보 정리는 금액·내부 연결 ID를 보존하는 식별 항목 제거 기능이다. 자유 입력 문서·백업·외부 CSV까지 자동으로 완전히 익명화하지 않는다.

## 7. 파일 구성과 검증

프런트엔드 수정 위치는 web/src, 자산 원본은 public/assets이다. 루트 index.html과 assets, 각 경로의 index.html은 기존 GitHub Pages main/root 배포를 위한 생성 파일이다. npm run build:pages로 갱신한다.

검증의 구체적 결과, 운영 배포 상태와 남은 위험은 [검증·보안 보고서](검증-보안-보고서.md)를 확인한다. 배포·개인정보 처리 기준은 [SECURITY.md](../SECURITY.md)를 따른다.

## 2026-09-09 역할 관리와 부원 등록 변경

- 부원 등록 자체가 가입·회비 확인 완료를 뜻한다. 화면·CSV에서 회비 납부 체크와 활동 상태를 제거하고 서버의 신청·대기 승급·수락에서 두 값을 자격 조건으로 사용하지 않는다. 등록 학기와 본인 정보, 개인정보 정리 여부는 계속 확인한다.
- 기존 status/duesPaid 필드는 이전 클라이언트 호환을 위해 입력은 허용하되 새 등록·수정 시 저장하지 않으며 조회에도 노출하지 않는다. 운영 DB 일괄 수정·삭제나 이전 회비 장부 이관은 실행하지 않는다.
- 성별 입력은 남성·여성 또는 미선택이며 기타 선택지는 없다.
- 역할 관리(/admin/roles)에서 역할을 생성·수정하고 임원 배정(/admin/admins)에서 배정한다. 사용자 정의 역할은 권한 관리 계정만 만들 수 있다.
- 기본 역할 표시는 owner=회장, chair=부회장, finance=재무부이며 기존 계정의 역할 코드는 변경하지 않는다. 기본 회비·정산 권한은 이 세 역할에만 있다. 사용자 정의 역할에 재무 권한을 주려면 회장이 명시적으로 선택해야 한다.
- 역할별 명부·행사·회계·재고·회의·결정·게시·설정·이력 권한은 서버에서 매 요청 다시 확인한다. 화면을 이동하거나 새로 읽을 때 권한과 메뉴를 갱신하고 권한 변경 시 화면 캐시를 비운다.
- 회비·정산 권한이 없으면 장부 조회·처리가 거부되고, 신청자 목록·상세의 납부 상태·납부액·환불액도 서버 응답에서 제외한다. 행사 안내용 참가비와 취소 정책은 행사 담당자가 확인할 수 있다.
- 역할·임원 관리 및 개인정보 정리는 회장의 필수 권한으로 유지한다. 회장 역할 자체의 변경, 자기 자신의 최종 관리 권한 해제, 배정 중인 역할 삭제, 중복 이름 및 오래된 버전 덮어쓰기를 차단한다.
- 역할과 임원 배정 기능은 앱 내부 권한만 관리한다. Firebase IAM·서비스 계정·Auth 계정 생성 기능과 분리되어 있다.


## 2026-09-09 학기별 부원 명부

- Firestore 저장 경로는 `martini_v2_semesters/{학기}/members/{부원ID}`이다. 예: `martini_v2_semesters/2026-2/members/{부원ID}`. 학생 문서에는 semester 필드를 저장하지 않는다. API가 구형 화면과의 호환을 위해 경로에서 학기를 계산해 응답할 수 있다.
- 명부 화면에서 학기 폴더를 선택한다. 다른 학기 열기로 새 학기를 열고 첫 부원을 등록하면 학기 폴더가 보존된다. 개별 등록·수정 화면과 표에는 등록 학기 칸을 두지 않는다. CSV도 선택 학기만 포함하며 파일명에 학기를 표시한다.
- 같은 학생의 다른 학기 가입은 별도 기록이다. 과거 명부를 다음 학기로 덮어쓰지 않는다. 행사 신청·대기 승급·연락처 조회는 행사 학기의 명부만 참조한다. 학기 회비 거래 연결은 `martini_v2_semesters/{학기}/dues/{부원ID}`에 보존하며 회비 금액 자체는 기존 장부에 남긴다.
- 개인정보 정리는 선택 학기의 명부와 연결 기록에만 적용한다. 다른 학기의 학생 정보는 유지한다. 기존 역할·서버 권한 검사와 클라이언트 직접 접근 차단은 유지한다.
- `node scripts/migrate-semester-roster.cjs`는 운영 명부 이전을 미리 점검하고 건수만 출력한다. `--apply`는 학생 ID·내용과 회비 장부 연결을 보존해 트랜잭션으로 옮기고 이전 경로를 제거한다. 충돌 시 덮어쓰지 않고 중단한다. 재실행해도 이미 옮긴 명부를 중복 생성하지 않는다. 기존 Firebase CLI 인증을 메모리에서 사용하며 개인정보·토큰·키는 출력하거나 파일에 저장하지 않는다.
- 배포 순서: 단위·통합·브라우저 검증 → 호환 읽기가 있는 서버 배포 → 이전 dry run → 이번 사용자 요청에 따른 명부 이전 → main 및 Pages 반영 → 실제 서비스 확인. 학기별 저장을 요청한 범위 외 운영 데이터는 변경하지 않는다.


## 2026-09-09 명부 제거·복구와 부원 메모

- 명부 관리 권한으로 선택 학기의 부원을 명부에서 제거하거나 복구한다. 화면에서 이름·학기를 확인하고 실행하며 서버는 권한·학기·수정 버전을 검증한다. 제거는 removedAt/removedBy 표시로 기록하고 일반 명부·인원 집계·신규 신청·대기 승급에서 제외한다. 기존 신청·정산·연락처 연결과 다른 학기의 명부는 유지한다. 개인정보 영구 삭제 기능과는 다르며 학기말 정리 대상에 계속 포함된다.
- 제거한 부원 보기에서 복구하면 같은 학생 ID가 유지된다. 같은 학번·연락처로 새 기록을 중복 생성하지 않는다. 개인정보를 이미 정리한 부원은 복구할 수 없다. 제거·복구는 변경 이력에 학기와 처리자를 남긴다.
- 부원 메모는 해당 학기 학생 문서의 note(최대 3000자)에 저장한다. 이름을 클릭한 상세 화면과 수정 폼에서만 표시한다. 일반/제거 목록 API 응답·목록 검색·CSV·공개 신청/영수증·행사 담당자의 연락처 조회에는 포함하지 않는다. 명부 조회 권한이 있어야 상세 메모를 읽을 수 있다. 개인정보 정리 시 메모도 비운다.
- 이번 작업은 기능 배포만 수행한다. 운영 중인 특정 부원을 실제로 제거하지 않으며, 이전에 승인 대기 중인 기존 명부 경로 이전도 실행하지 않는다.
