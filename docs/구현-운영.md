# 마티니 v2 구현 · 운영 안내

작성일: 2026-09-08

이 문서는 구현·배포 결과와 운영자가 입력할 실제 정보, 인수인계 작업을 설명한다. 회의록이나 동아리의 실제 결정 사항을 이 파일로 관리하는 것은 아니다. 실제 회의·안건·결정·후속 업무는 운영실에서 Firestore에 저장한다.

## 1. 사용자 답변에 따른 변경

| 사용자 답변 | 적용 |
|---|---|
| 친목 중심, 교육과 개강총회 | 공개 소개와 행사 유형을 교육·총회·친목 중심으로 구성 |
| 임원 11명, 5개 부서 | 회장단·교육부·집행부·총무부·홍보부 및 운영 책임자 역할 |
| 일반 부원 로그인 불필요 | 일반 부원 계정·회원가입·내 프로필을 제거하고 행사/개인 확인 링크 사용 |
| 기존 명부 수기 입력 | 부원 등록·수정과 현재 학기 활동·회비 상태 관리 |
| 오픈채팅 가입 안내 | 가입 안내에서 운영 설정에 입력한 카카오톡 오픈채팅으로 연결 |
| 회비 학기제, 임원도 납부 | 임원 여부로 납부 확인을 면제하지 않음 |
| 미납자는 활동 불가 | 서버에서 명부·현재 학기·활동·회비 확인 |
| 술 외 재료·도구도 관리 | 주류·재료·소모품·도구 분류 |
| 개봉 잔량 10% 단계 | 병별 0~100% 기록, 입고·사용·실사·정정 이력 |
| 알림·QR 불필요 | 직접 공지, 이름을 호명한 뒤 수기 출석 표시 |
| 외부인·팀·투표 불필요 | 해당 기능 제외 |
| 회의·결정은 데이터베이스 저장 | 회의 본문, 구조화한 안건, 연결된 결정·할 일, 수정 버전 저장 |

## 2. 임의로 정한 기본 운영 방식

- 일반 신청의 자격 확인 항목: 이름·학번·전체 전화번호. 공개 명부 검색은 제공하지 않는다.
- 대기자는 접수 순서대로 운영진이 승급을 제안한다. 제안 중인 좌석도 정원에 포함한다.
- 승급 제안의 기본 응답 시간은 6시간이며 행사 시작 이전으로 수정할 수 있다.
- 응답 기한이 지난 제안은 임원이 확인한 뒤 해제한다. 자동 알림·자동 배치는 없다.
- 행사 생성 초기값: 초안, 20명, 1주 뒤 일정, 전날 신청·자율 취소 마감. 실제 게시 전 수정한다.
- 무료 행사로 시작하며 유료 행사는 참가비·납부 안내를 입력해야 한다.
- 납부 확인·지출·환불 기록은 총무부 또는 회장단이 실제 거래 확인 후 입력한다.
- 노쇼에 자동 제재를 부과하지 않는다.
- 기록된 회비를 새 학기로 자동 승계하지 않는다.
- 휴동·탈퇴·졸업은 신청 자격을 즉시 중지한다. 기존 정산·신청 연결을 깨뜨리는 즉시 영구 삭제는 하지 않는다.
- 개봉 병 잔량을 늘리는 실사 정정은 일반 사용과 구분하고 사유를 남긴다.
- 잔량이 있는 재고의 관리 단위·병 규격은 변경할 수 없다.
- 결정에 연결된 회의 안건은 연결을 먼저 바꾼 뒤 제거한다.
- 확정 회의록의 정정은 회장단·운영 책임자만 가능하다.
- 공개 콘텐츠는 직접 공개 상태로 지정해야 홈페이지에 나온다.

## 3. 주요 화면

| 주소 | 기능 |
|---|---|
| / | 마티니 소개 |
| /about | 동아리 방향·공간·운영 |
| /activities | 교육·총회 소개, 공개 활동 기록 |
| /join | 오픈채팅 가입 안내 |
| /notices | 공개 공지 |
| /privacy | GitHub 개편 전 개인정보 처리방침 원문 |
| /e/{eventId}#key=… | 로그인 없는 행사 상세·신청 |
| /r/{applicationId}#key=… | 개인 신청 확인·취소·입금 확인 요청·대기 수락 |
| /admin | 담당 업무 요약 |
| /admin/events | 행사 생성·편집·공유 링크 |
| /admin/events/{id} | 신청·수기 출석·납부·대기 처리 |
| /admin/members | 명부·학기·활동·회비 상태 |
| /admin/inventory | 재고·병별 잔량·입출고·실사 |
| /admin/finance | 회비·수입·지출·환불 |
| /admin/meetings | 회의록·안건·논의·수정 이력 |
| /admin/decisions | 결정·업무·담당자·기한·상태 |
| /admin/content | 공개 공지·활동 기록 |
| /admin/settings | 기록 구분 학기·활동 장소·소개·가입 오픈채팅·문의 채널 |
| /admin/admins | 임원 UID·부서 권한·임기 |
| /admin/audit | 주요 변경·내보내기 이력 |

임원 모바일 화면은 하단 메뉴에서 주요 작업에 접근하고 전체 메뉴를 열 수 있다. 넓은 목록은 카드형 행으로 표시한다.

## 4. 실제 데이터 저장 구조

- martini_v2_admins: 임원 권한과 임기.
- martini_v2_settings/club: 현재 학기와 운영 안내.
- martini_v2_members: 부원 명부.
- members/{id}/semesters: 학기별 활동 상태 이력.
- martini_v2_events: 행사, 정원, 등록·대기 수, 링크 해시.
- martini_v2_applications: 신청·납부·출석·확인 링크 해시.
- applications/{id}/history: 취소 후 재신청 이전 기록.
- martini_v2_inventory: 품목, 규격, 미개봉·일반 수량, 개봉 병 잔량.
- martini_v2_stockMoves: 재고 변경 전후 수치·사유·담당자·행사.
- martini_v2_finance: 확인한 입금·지출·환불.
- martini_v2_meetings: 회의와 안건.
- meetings/{id}/revisions: 회의록 수정 시점별 원문.
- martini_v2_decisions: 회의/안건에 연결된 결정·후속 업무.
- decisions/{id}/revisions: 결정 기록의 수정 버전.
- martini_v2_content: 공개 공지·활동 기록.
- martini_v2_audit: 중요 운영 변경과 내보내기 기록.
- martini_v2_rateLimits: 공개 요청 제한. 만료 필드의 TTL 적용은 별도 운영 승인 필요.

위 하위 컬렉션의 부모 이름에는 실제로 martini_v2_ 접두사가 포함된다. 설명에서만 축약했다.

## 5. 최신 구현·배포

- 배경과 로고를 public/assets로 이동하고 검정·금색 톤을 공개 화면, 신청, 운영실, 폼과 모달에 통일했다.
- 모바일 메뉴·운영 하단 메뉴·표 카드 전환을 제공한다.
- 회의 선택과 재고 이력은 오래된 기록도 조회하며, 연결 관계를 보존한다.
- 회비 수기 확인과 회계 장부 연결을 분리해 장부를 한 번 보충할 수 있다.
- 행사 취소 시 신청·대기·예약을 함께 종료하며, 출석 이력은 보존하고 추가 입금은 막는다.
- 대기 제안·수락 시 자격을 재확인하고 제안 거절은 일반 취소 마감과 분리한다.
- 학기말 개인정보 대상·미정산·건수·수정 여부를 검토하는 owner 전용 정리 화면을 제공한다.
- 대시보드와 재무 요약은 전체 기록을 불러와 계산한다.
- 서버·Firestore/Storage 규칙은 실제 Firebase 프로젝트에 적용했다. 기존 컬렉션은 이관하거나 지우지 않았다.
- 최초 운영자 계정·권한을 준비했고 비밀번호 설정 메일을 요청했다.
- App Check의 기존 Auth/Firestore/Storage 강제를 유지하고 실제 도메인에서 클라이언트 초기화를 활성화했다.

## 6. 운영자가 입력할 실제 정보

운영실에서 현재 학기, 활동 장소, 소개, 가입 오픈채팅 링크와 문의 채널을 입력한다. 가입 방법은 오픈채팅에서 안내한다. 회비는 실제 입금액을 장부에 기록하며, 설정에서 금액이나 기간을 정하지 않는다. 개인정보 페이지는 기존 GitHub 원문을 표시한다. 실제 명부와 재고는 가상 데이터로 채우지 않았다. 부원 입력과 납부 확인 후 첫 행사를 모집한다.

초기 owner 임기는 2027-02-28 23:59:59 KST이다. 임기 전에 후임 운영자를 등록한다.

개인정보 정리는 금액·내부 연결 ID를 보존하는 식별 항목 제거 기능이다. 자유 입력 문서·백업·외부 CSV까지 자동으로 완전히 익명화하지 않는다.

## 7. 파일 구성과 검증

프런트엔드 수정 위치는 web/src, 자산 원본은 public/assets이다. 루트 index.html과 assets, 각 경로의 index.html은 기존 GitHub Pages main/root 배포를 위한 생성 파일이다. npm run build:pages로 갱신한다.

검증의 구체적 결과, 운영 배포 상태와 남은 위험은 [검증·보안 보고서](검증-보안-보고서.md)를 확인한다. 배포·개인정보 처리 기준은 [SECURITY.md](../SECURITY.md)를 따른다.
