## [5] High / Medium / Low 위험

### High

- 운영 함수·규칙 배포, 최초 운영자 생성, main 공개 반영은 운영 영향이 큰 작업이며 사용자 승인을 받고 진행했다.
- 새 차단 규칙으로 구형 클라이언트의 직접 Firestore/Storage 접근은 종료됐다. 과거 화면만 복구해도 과거 데이터 접근이 복구되지는 않는다.
- 기본 검사에서 노출된 비밀 키 또는 폭넓은 공개 쓰기 권한은 발견하지 않았다.

### Medium

- 새 callable의 enforceAppCheck는 false이다. Auth·Firestore·Storage의 기존 강제 적용은 유지한다. 함수 강제 적용 변경은 사용자 지표 확인과 별도 승인이 필요하다.
- rateLimits 만료 필드만으로 문서가 자동 삭제되지 않는다. TTL·백업·보존 정책을 운영자가 확인해야 한다.
- 함수 생성은 성공했지만 Artifact Registry 빌드 이미지 정리 정책이 없어 마지막 배포 명령은 정리 정책 경고와 종료 코드 1을 반환했다. 이미지 보관에 비용이 발생할 수 있다. 새 인프라 정책을 임의로 추가하지 않았다.
- 개발 도구 포함 npm audit에 Moderate 7개 경고가 남아 있다. 프런트엔드·Functions의 운영 의존성에는 보고된 취약점이 없다.
- 개인 확인 링크는 접근 권한을 가진 링크이며 본인에게만 전달해야 한다. 개인정보 정리는 금액·내부 연결을 보존하므로 자유 입력 문서·CSV·백업까지 완전히 익명화하지 않는다.
- 에뮬레이터 부하 검증은 운영 환경의 성능 보장이 아니다.
- 실제 사이트에서 자동화 Chrome의 App Check 요청은 HTTP 403 / PERMISSION_DENIED / App attestation failed로 거절됐다. 키·도메인·Enterprise SCORE 공급자 연결은 일치하고 기존 최소 점수 0.5를 유지했다. 자동화 평가 때문일 가능성이 있지만 원인은 확정하지 않았다. 이후 사용자가 일반 Chrome에서 운영자 로그인 성공을 직접 확인했다. 자동화 검증 결과와 실제 사용자 로그인 결과를 구분한다.

### Low

- Firebase Web config와 App Check 사이트 키는 공개 클라이언트 설정이다.
- 실제 회비·문의처·개인정보 안내·가입 URL·명부·재고는 운영자가 입력해야 한다. 가상 정보를 운영 DB에 넣지 않았다.

4. 2027-02-28 임기 만료 전 후임 owner 준비.
5. 별도 운영 정책으로 TTL·이미지 정리·백업·보존 기간 검토.
