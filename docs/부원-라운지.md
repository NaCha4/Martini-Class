# 부원 라운지와 외부인 출입 승인

2026-09-12 추가, 2026-10-03 로그인 유지 방식 갱신. 부원 페이지 `/members/`, 운영진 처리 목록 `/admin/requests/`.

## 이용 흐름

1. 라운지에 들어가면 현재 학기 명부에 등록된 이름·학번으로 로그인한다. 새 로그인은 같은 브라우저에서 최대 7일 유지되며 서버가 현재 명부 자격을 계속 확인한다. 유효한 쿠키가 있으면 이름·학번을 다시 입력하지 않고 이용한다.
2. 로그인 후 외부인 출입신청·행사·제휴 카드와 그 아래의 내 신청 내역을 확인한다. 카드를 누르면 팝업에서 신청하거나 내용을 조회한다. 라운지에는 공지와 준비 중 쿠폰 화면을 표시하지 않는다.
3. 외부인 출입 신청을 열고 월간 달력에서 방문 날짜를 선택한다. 시작 시간, 인원, 방문 사유, 외부인 이름을 입력하고 개인정보 안내에 동의해 접수한다. 선택 날짜·시간·인원이 요약되며 월을 이동해도 입력을 유지한다. 종료시간과 다음 날 종료 여부는 받지 않는다. 한국 시간 기준으로 90일 이내 방문, 외부인 1~3명을 받으며 서버에서도 같은 인원 제한을 적용한다. PC는 달력과 입력란을 나란히, 모바일은 위아래로 표시한다.
4. 운영진은 신청 · 문의에서 내용을 검토하고 승인·반려·답변한다. 반려와 문의 답변은 안내 문구를 반드시 입력한다. 요청자는 내 신청 내역에서 결과를 확인한다.
5. 승인된 시간과 인원에 한해 신청 부원과 동행한다. 시작 시간이 지난 방문은 승인하지 않는다. 승인 전후에 부원의 현재 명부 자격을 검사한다.

동아리 가입 신청은 운영진이 별도 Google Form으로 처리한다. 라운지에는 가입 카드·폼과 서버의 신규 가입 접수를 제공하지 않는다. 기존 `/join` 오픈채팅 안내와 관련 설정은 유지한다.

이전에 라운지로 접수된 가입 기록은 삭제하지 않는다. 기존 개인 확인 링크로 결과를 조회할 수 있고, 운영진도 기존 권한으로 조회·승인·반려할 수 있다. 운영실에는 가입 요약 카드가 없으며, 불러온 기록에 이전 가입 신청이 있을 때만 종류 필터에 ‘이전 가입 신청’을 표시한다. 이전 가입 신청의 승인은 검토 결과이며 명부 등록이나 회비 처리를 자동 실행하지 않는다.

문자·이메일·카카오톡 자동 알림은 없다. 신청자는 페이지 또는 보관한 개인 신청 확인 링크에서 결과를 확인한다. 공용 기기에서는 라운지 상단의 ‘로그아웃’으로 해당 서버 세션을 해지하고 브라우저의 로그인·조회 정보를 지운다. 창을 닫는 것만으로 7일 쿠키가 지워지지는 않는다.

## 로그인 유지

- 새 라운지 로그인은 `memberAccess`에 `remember: true`를 보내며 발급 시점부터 최대 7일 유효하다. 옵션이 없는 구형 클라이언트는 2시간 세션을 발급받는다. 이미 발급된 세션은 그대로의 만료 시각을 유지하고 재시도·새로고침·재방문으로 유효기간을 늘리지 않는다.
- 쿠키에는 무작위 세션 토큰과 서버의 고정 만료 시각만 보관한다. 이름·학번·전화번호는 저장하지 않으며 검증된 이름은 메모리에서만 사용한다. 개인 확인 링크와 접수 복구 정보는 기존의 탭 단위 `sessionStorage`를 사용하며 로그인 유지 쿠키와 구분한다.
- 운영 쿠키는 `__Host-` 접두사와 `Domain` 없는 호스트 전용 쿠키이며 `Path=/`, `Secure`, `SameSite=Lax`와 만료를 설정한다. HTTPS가 아닌 곳에서는 개발용 로컬 호스트만 예외로 허용한다. 다른 호스트나 하위 도메인으로 로그인 쿠키를 공유하지 않는다.
- GitHub Pages 화면이 쿠키의 토큰을 읽어 Firebase callable 요청에 직접 전달하는 구조이므로 `HttpOnly` 쿠키는 아니다. JavaScript에서 접근할 수 있는 토큰이며 XSS나 기기 접근으로 탈취되면 만료·해지 전까지 사용될 수 있다. 쿠키는 강한 본인 인증을 추가하는 기능이 아니다.
- 재방문 시 쿠키만 보고 부원 정보를 표시하지 않고 서버의 세션·현재 명부 검증을 거친다. 만료, 로그아웃으로 인한 해지, 명부 제거·개인정보 정리·신원 정보 또는 현재 학기 변경 시 다시 로그인해야 한다.
- 로그아웃은 그 토큰의 세션 해지를 요청한다. 다른 기기의 로그인과 기존 개인 신청 확인 링크를 일괄 폐기하지 않는다. 서버 연결이 끊기면 로컬 로그인 정보를 지운 뒤 서버 해지를 확인하지 못했다고 표시한다. 쿠키를 직접 지우면 해당 브라우저의 재방문 로그인은 해제되지만 서버 세션 해지는 앱의 로그아웃을 이용한다.
- 브라우저에서 쿠키 저장이 차단되면 로그인은 현재 열린 탭에서만 유지되며 로그인 후 안내한다. 쿠키 삭제가 실패하면 브라우저 설정에서 사이트 쿠키·데이터를 지우도록 안내한다.

## 접근 및 데이터

- 기존 `members` 업무 권한을 가진 임원만 신청 목록과 상세 내용를 조회하고 처리한다. 회장·부회장·집행부·재무부 기본 역할과 해당 권한을 가진 사용자 정의 역할에 적용된다. 실제 역할 배정이나 IAM은 바꾸지 않는다.
- 부원 확인은 명부 정보 대조 방식이며 이메일/휴대전화 소유 인증은 아니다. 신원 정보가 다른 사람에게 알려지지 않도록 관리한다. 요청마다 학기·명부 상태와 신원 정보 변경 여부를 재확인한다.
- 라운지의 부원 확인과 비회원 문의는 이름·학번만 받는다. 새 출입 신청·문의에 전화번호를 복사하거나 저장하지 않으며 응답과 운영진 상세에도 제공하지 않는다. 기존 명부와 접수 기록은 수정하지 않는다. 배포 전 화면이 보내는 전화번호 필드는 호환을 위해 무시한다.
- 새 부원 신청에는 기존 명부 정보의 대조 해시만 저장해 명부 재할당·정보 변경을 검사한다. 이전 신청은 기존 정보로 같은 검사를 수행하며 기존 개인 확인 링크와 중복 접수 복구를 지원한다.
- `martini_v2_memberSessions`에는 무작위 256비트 접근 값의 해시, 부원 연결 ID, 학기, 정보 대조 해시와 고정 만료 시각을 저장한다. 새 로그인 유지 세션은 최대 7일, 구형 클라이언트 세션은 2시간이다. 로그아웃한 세션은 해지 표시를 검사해 거부한다. 실제 토큰은 서버 문서에 저장하지 않는다.
- `martini_v2_clubRequests`에는 방문·문의와 결과를 저장하며 이전 가입 접수 기록도 보존한다. 신규 가입 접수 요청은 서버에서 거부한다. 개인 확인용 값은 서버에 해시만 저장한다. 부원 세션 토큰과 개인 확인 토큰은 서로 다르며, 신청 확인 링크에는 해당 신청 토큰만 들어간다.
- 직접 Firestore/Storage 접근은 기존과 같이 차단한다. 검증된 callable 함수만 데이터를 읽고 쓴다. IP와 신원/접근 식별자별 요청 제한을 적용한다.
- 중복 접수는 동일 요청 ID·확인 값·내용에 대해서만 같은 결과를 반환한다. 운영진 결정과 취소는 트랜잭션으로 기록하고 revision으로 동시 변경을 차단한다.
- 부원별 내역 조회용 `memberScope ASC, createdAt DESC` 복합 색인이 필요하다. 색인을 먼저 준비한 뒤 기존 callable 함수, 마지막으로 클라이언트를 배포한다.

## 보관과 운영

새 방문 기록은 방문 시작 후 180일(기존 기록의 보관 검토 시각은 유지), 이전 가입 접수 기록은 승인·반려 후 365일, 문의는 답변 후 180일을 보관 검토 기준으로 기록한다. 취소한 신청은 취소 시점부터 해당 기간으로 검토한다. `retentionUntil`은 검토 시각이며 자동 삭제되지 않는다. 대기 중인 이전 가입 접수 기록과 문의도 주기적으로 처리 상태와 보관 필요성을 확인한다.

기존 학기말 개인정보 정리 화면은 행사 신청·명부를 대상으로 하며 라운지의 출입·문의·이전 가입 접수 기록과 세션을 자동 정리하지 않는다. 담당자가 별도로 검토하고 운영 자료 정리 승인을 받은 후 삭제해야 한다. 세션의 접근 유효성은 문서 삭제와 관계없이 발급 당시의 만료 시각이나 로그아웃 해지 시점에 끝난다. TTL 설정·자동 삭제 작업·운영 데이터 일괄 수정은 이번 코드 배포 범위에 포함하지 않는다.

실제 행사·공지·명부를 가상 기록으로 채우지 않는다. 화면에 표시할 자료는 기존 운영 화면에서 등록한다. 테스트 자료는 `demo-*` 에뮬레이터 프로젝트에만 작성한다.

## 배포 확인

- 비밀 정보 검사, 단위·통합 테스트 및 데스크톱·모바일 브라우저 흐름 검증.
- Firestore 복합 색인 준비 → Firebase `martiniApi` 함수 → `build:pages` 산출물과 main 반영 → GitHub Pages 확인.
- 기존 Firestore/Storage 차단 규칙, App Check, 키, IAM, 도메인, 과금 설정 유지.
- 운영 자료에 테스트 신청·승인·이관·삭제를 실행하지 않음.

2026-10-03 로그인 유지 변경은 서버의 `remember` 옵션·로그아웃 API를 먼저 배포하고 웹을 이어 배포한다. Java와 지정된 Browser 플러그인이 없는 현재 작업 환경에서는 에뮬레이터 통합·실제 브라우저 쿠키 검사를 실행할 수 없다. 단위 검사로 고정 7일 만료·구형 2시간 호환·해지·쿠키 저장/제거·로그인 전 접근 차단을 확인하고, 브라우저 재시작 후 재방문과 다른 탭의 로그아웃 반영은 브라우저 환경에서 추가 확인할 항목으로 구분한다.
