# UI·UX 개선 기록

2026-09-08 · 마티니 운영 시스템

배경 사진, 로고와 검정·금색 톤을 유지하면서 화면 안정성, 입력 실수 예방, 키보드·모바일 조작을 개선했다.

## 적용한 원칙과 실제 변경

| 원칙 | 기존 불편 | 적용 |
| --- | --- | --- |
| 시각적 안정성과 일관성 | 스크롤바가 생기거나 로딩 화면으로 바뀌면서 좌우·상하 위치가 달라짐 | 루트에 scrollbar-gutter: stable을 적용하고, 재조회 중 기존 화면·높이·스크롤을 유지한다. 모달도 같은 너비를 유지하며 배경 스크롤을 잠근다. |
| 시스템 상태 가시성 | 클릭 뒤 처리 중인지 알기 어렵고 중복 요청 가능 | 상단 진행 표시, 버튼 진행 문구·aria-busy, 중복 실행 방지, 실패 시 버튼과 입력 복구 |
| 오류 예방과 사용자 통제 | 회의록을 닫거나 뒤로가기를 누르면 작성 내용 소실 | 변경된 모달은 계속 작성/변경사항 버리기 확인. 신청서도 링크 이동·뒤로가기·새로고침 전에 작성 상태를 확인한다. 입력은 메모리에만 유지하고 별도 저장소에 개인정보 초안을 저장하지 않는다. |
| 피츠의 법칙과 조작 면적 | 작은 기록·수정·닫기 버튼을 잘못 누르기 쉬움 | 주요 터치 대상 44px 목표, 버튼 간격, 모바일 안전 영역, 긴 모달에서 제목과 저장 버튼을 고정 |
| 선택 부담 감소와 점진적 공개 | 재고 작업과 무관한 입력이 함께 나오고 검증에 걸림 | 작업 종류에 맞는 수량·병·잔량·위치만 표시한다. 숨긴 입력은 비활성화해 브라우저 검증에서 제외한다. 권한에 맞는 작업과 대시보드만 표시한다. |
| 기억보다 인식 | 검색 0건과 빈 목록을 구분하기 어렵고 링크·내보내기 범위가 불명확 | 모바일에도 불러온 기록/결과 수 표시, 검색 초기화, 빈 상태의 다음 행동, 개인 확인 링크 보관 안내, CSV 범위 설명 |
| 접근성과 예측 가능한 이동 | 새 화면·오류 위치·닫은 모달의 포커스 위치를 알기 어려움 | 화면 제목으로 포커스 이동, 모달 시작·복귀 위치 관리, 기본 새 탭 동작 유지, 필드 레이블과 도움말 연결, 오류 강조와 포커스 이동, 비밀번호 표시/숨김 |
| 현실과 화면의 일치 | 접수 번호가 대기 순위로 보이거나 마감 이후에도 취소를 시도하게 됨 | 실제 대기자 우선 처리·신청 기간·취소 기한에 맞는 안내. 접수 번호와 대기 순위 구분, 입금 확인 절차, 취소·환불 상태 설명 |

핵심 조작을 44px로 잡은 것은 프로젝트의 사용성 목표다. WCAG 2.2의 최소 타깃 크기 기준은 예외·간격 조건과 함께 24px를 제시한다. 이 작업을 전체 WCAG 적합성 인증으로 표현하지 않는다. [W3C 타깃 크기 지침](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

모달은 네이티브 dialog의 키보드 동작을 사용하고, 긴 내용의 시작점과 닫은 뒤 돌아갈 위치를 관리한다. [W3C 모달 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

스크롤바 공간 예약은 브라우저 기본 스크롤바를 유지한다. 지원하지 않는 브라우저에는 지속 스크롤 영역과 모달 너비 보정을 제공한다. [MDN scrollbar-gutter](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/scrollbar-gutter)

## 운영 화면의 추가 개선

- 최초 운영 설정으로 이어지는 안내와 권한별 대시보드
- 행사 취소가 모든 신청에 미치는 영향과 필수 확인
- 신청/개인 확인 링크의 재발급 의미, 읽기 전용 복사 입력
- 회의 안건 제거 전 확인과 입력 위치 복귀
- 참가비·학기 변경 제한을 화면에도 반영
- 운영 설정·공개 콘텐츠 저장 후 공개 정보 캐시 갱신
- 서버 오류가 나면 입력을 유지하고 오류 위치에서 재시도
- 저장 중에는 입력과 닫기를 보호해 보낸 값과 화면 값이 어긋나지 않도록 처리

## 검증

- 단위 테스트 8개 통과.
- Chrome 데스크톱·모바일 브라우저 테스트 총 26개 통과.
- 실제 신청·취소, 회의·결정·수정 이력, 재고·회계 흐름을 함께 검증했다.
- 짧고 긴 문서 및 모달 열기 전후 기준 요소의 가로 위치·너비 변화가 1px 이내인지 확인했다.
- 모달 배경 휠 차단, Escape와 포커스 복귀, 변경 내용 보존, 중복 저장·실패 후 재시도를 검증했다.
- 지연된 API 조회 중 기존 화면 유지, 검색 0건 복구, 키보드 이동, 작성 중 뒤로가기의 URL·입력 복구를 검증했다.
- 1440px, 390px, 320px 화면에서 긴 회의 모달의 제목·저장 버튼 가시성과 가로 넘침을 확인했다.
- 안건 제거 취소 시 내용 보존 및 행사 취소 확인 체크를 별도로 확인했다.
- 배포 빌드 통과: JS 236.11kB/gzip 73.82kB, CSS 42.35kB/gzip 9.70kB.
- 실제 hyu-martini.site에서 데스크톱·모바일 UI 검증 통과: 최신 자산, 스크롤 공간, 모달 너비, 작성 내용 보호, 비밀번호 표시·숨김, 가로 넘침·스크립트 오류 없음.
- 실제 iOS Safari 실기기나 모든 보조공학 조합을 검증한 것은 아니다.

개발 서버는 HMR 시 main.js에 버전 쿼리를 붙인다. 테스트는 실제 로드된 모듈 URL을 재사용해 앱의 이벤트 리스너와 상태가 중복 생성되지 않게 한다.

## 변경 범위와 공개 반영

프런트엔드 소스 web/src/{main,ui,style,public,admin,admin-forms}, 브라우저 회귀 테스트, 문서 및 GitHub Pages 빌드 산출물에 한정한다.

Firebase 함수·Security Rules·App Check·역할 권한·데이터 스키마는 변경하지 않는다. 로컬 가상 데이터로 검증하며, 실제 운영 자료를 수정하는 테스트는 하지 않는다.

기존에 승인된 main push 범위로 반영했다. 구현 커밋 681a9b1, GitHub Pages 작업 34223116813의 success와 실제 사이트의 최신 자산을 확인했다. 공개 화면과 로그인 폼의 스크롤·모달 동작을 확인했고, 운영자 계정 비밀번호 입력이나 메일 재발송은 수행하지 않았다.

실제 사이트 UI 검증은 node tests/production-ui.mjs로 다시 실행할 수 있다. 서버 인증 성공을 별도로 요구하는 기존 production-smoke.mjs와 목적이 다르며, App Check 보호를 해제하지 않는다.
