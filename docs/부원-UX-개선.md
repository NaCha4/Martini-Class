# 부원 홈 · 행사 · 내 신청 · 쿠폰 준비 화면

2026-10-03. 부원 UX 구현·검증 기록이다. 후속 사용자 승인으로 main 커밋·push와 기존 공식 경로의 배포를 진행한다. 운영 데이터·권한·보안 설정은 변경하지 않는다.

## 화면과 이동

- 공개 홈페이지에서 부원 라운지로 바로 진입한다. 운영자 링크는 보조 영역에 둔다.
- 부원 메뉴는 홈 / 행사 / 내 신청 / 쿠폰 / 더보기로 통일한다.
- 홈은 다음 행사, 응답·납부가 필요한 행사 신청, 쿠폰 준비 안내를 먼저 표시한다.
- 외부인 출입 신청과 문의는 더보기에서 접수하고 내 신청에서 결과를 조회한다.
- `/events`는 기존 주소를 유지하며 실제 부원 행사 목록을 표시한다.
- 부원 행사·신청 상세에서 부원 확인이 필요하면 같은 목적지에서 확인한 뒤 이어서 진행한다.
- 확인한 부원의 행사 신청은 서버가 검증된 명부 정보를 사용한다. 공개 행사 링크의 기존 이름·학번 입력도 계속 지원한다.
- 개인정보 추가 안내를 현재 입력 항목에 맞춘다. 기존 개인정보 본문과 이전 가입 신청 조회·처리 호환은 보존한다.

## 신청 조회와 안전한 호환

새 행사 신청에는 명부 신원 대조 해시를 저장한다. 부원 세션을 사용하는 목록·상세 요청은 현재 학기와 명부 상태, 신청의 신원 대조 해시를 서버에서 검사한다. 세션 접근값·대조 해시·개인 확인 값은 조회 결과에 포함하지 않는다.

이전 행사 신청에는 신원 대조 해시가 없다. 행의 ID나 이름만으로 현재 명부 사용자에게 소유권을 부여하지 않으며, 해당 기록은 기존 `/r` 개인 확인 링크에서 계속 조회·처리한다. 운영 자료를 자동으로 이관하거나 기존 기록을 수정하지 않는다.

부원 세션과 개인 확인 링크는 서로 다른 접근 수단이다. 기존 정원·대기·참가 제안·취소·납부·환불 처리는 공통 서버 로직을 통해 유지한다. 세션을 지우거나 만료가 확인되면 부원 데이터가 남아 보이지 않도록 처리한다.

## 필링파인 쿠폰

확정 사항은 **한 쿠폰에 최대 10개 스탬프**이며 상품은 미정이다.

- 화면의 10개 빈칸은 구성 미리보기이며 실제 적립 잔액이 아니다.
- 쿠폰 API는 부원 세션을 검증하고 준비 상태만 반환한다.
- 적립·사용·발급·QR 생성 API는 활성화하지 않는다.
- 순수 도메인 함수는 0~10 정수 잔액, 적립 상한, 같은 요청 재전송과 수정 버전을 검증한다. 향후 실제 적립을 제공할 때에는 쿠폰과 요청 기록을 같은 서버 트랜잭션에서 읽고 저장해야 한다.
- 10개가 되어도 자동 사용·차감·초기화·상품 지급을 하지 않는다.
- 적립 구매 기준, 매장 처리자와 전용 권한, 본인 확인 수준, 유효기간·이월·오처리 정정 정책이 확정되기 전에는 실운영을 활성화하지 않는다.

이름·학번 대조는 금융성 혜택의 소유를 보장하는 인증으로 간주하지 않는다. 향후 QR에는 개인정보·부원 세션·기존 신청 확인 값을 넣지 않으며, QR 스캔만으로 쓰기를 수행하지 않는 별도 설계가 필요하다.

## 코드와 검증

공개 틀, 행사 신청·상태, 부원 세션·메뉴·쿠폰, 목록 필터와 화면 dispatch를 분리한다. 기존 임원 운영 기능, 온더락의 내부 고정 학기, `/join`, 이전 가입 신청, `duesPaid` 호환 필드와 테스트를 보존한다. 새 의존성·계정·키·권한 배정·App Check 설정 변경은 없다.
