# 사진과 카테고리 중심 재고 관리 · 2026-10-05

관리자 재고 표를 사진 카드 보드로 변경했다. 새 품목은 이름만으로 등록할 수 있고 사진은 선택 사항이다. 카테고리는 직접 만들고 이름을 바꿀 수 있으며, 카드의 이동 버튼을 다른 카테고리로 드래그하거나 클릭하여 이동한다. 모바일·키보드 사용자는 카테고리 선택창으로 같은 작업을 수행한다.

## 사용자 흐름

- 이름과 사진을 등록한다. 기본 수량은 0개이고, 단위·병 용량·최소 보유량·보관 위치·메모는 접힌 선택 설정에 있다.
- 새 카테고리는 빈 상태로도 표시한다. 카테고리 안의 품목 추가 버튼은 해당 카테고리에 바로 등록한다.
- 이름·보관 위치 검색은 모든 페이지에서 불러온 품목을 대상으로 한다.
- 품목 상세에서 사진 변경·수량 기록·개봉 잔량·이력·삭제 기능을 사용할 수 있다. 재고가 남은 품목 삭제 제한은 기존대로 적용한다.
- 비어 있는 사용자 카테고리만 삭제한다. 기존 주류·재료·소모품·도구 분류는 해당 품목이 있는 동안 표시하고, 다른 카테고리로 옮길 수 있다.

## 변경 파일과 저장 방식

- `web/src/inventory.js`, `inventory.css`: 카테고리 보드, 검색, 드래그·선택 이동, 생성·이름 수정·빈 카테고리 삭제.
- `web/src/inventory-forms.js`, `admin-forms.js`: 간단한 등록·수정, 사진 준비·미리보기, 상세 연결.
- `web/src/admin.js`, `main.js`: 관리자 화면과 이벤트 연결.
- `functions/src/domain.js`, `service.js`, `inventory-board.js`, `inventory-photo.js`: 사진·입력 검증, 카테고리·이동 API, 기존 데이터 호환.
- `tests/inventory-*.test.mjs`, `tests/admin-retired-ui.test.mjs`, `package.json`: 회귀 검증과 실행 목록.
- `README.md`, 이 문서, 빌드된 Pages HTML·JS·CSS: 사용 안내와 공개 산출물.

사진은 브라우저에서 긴 변 최대 640px, 150,000자 이하 JPEG 데이터로 줄인다. 서버는 160,000자 이내 JPG·PNG·WebP 데이터와 파일 식별자를 검증한다. 외부 URL·SVG는 허용하지 않는다. 작은 미리보기를 기존 품목 문서의 `photo`에 저장하므로 Storage 규칙과 공개 업로드 경로를 추가하지 않는다. 목록을 한꺼번에 읽기 때문에 사진 품목이 많아지면 전송량이 증가하는 한계가 있다.

사용자 카테고리는 `martini_v2_inventoryCategories`, 이름 중복 방지는 `martini_v2_inventoryCategoryNames`에 저장한다. 품목의 `categoryId`가 없으면 기존 분류를 읽을 때만 가상 카테고리로 연결한다. 배포 시 운영 자료 일괄 변경은 하지 않는다. 이름·사진 수정에서 생략된 단위·위치·메모·분류·수량·개봉 기록은 보존한다.

이동 API는 카테고리·수정 버전·변경 메타데이터만 수정한다. 기존 재고 권한과 임기·인증 검사를 사용하고, 오래된 버전의 수정과 카테고리 삭제/추가 경합을 트랜잭션으로 막는다. 감사 로그에 사진 데이터는 넣지 않는다.

## 검증과 배포

단위·화면 로직·폼·사진 검증과 Firestore 에뮬레이터 통합 테스트를 수행한다. 실제 코드의 드래그/드롭 이벤트·실패 처리·선택창·검색을 Node 테스트로 확인한다. 이 세션에는 지정된 Browser/Chrome 확장 연결이 없어 실제 브라우저 렌더링, 터치 조작, 실제 이미지 디코딩은 검증하지 못했다.

배포 순서는 호환 서버 `functions:martini-v2:martiniApi` → main의 Pages 산출물 → Firebase Hosting이다. 기존 사용자 배포 승인 범위로 진행하며, IAM·키·과금·도메인·보안 규칙·App Check 설정 변경과 운영 재고 입력·삭제·이관은 수행하지 않는다.

최종 소스는 원격 main의 쿠폰·예산·부원 관련 변경까지 보존하여 병합했다. `npm test` 287개, `npm run test:integration` 126개가 모두 통과했다. JavaScript 문법 94개 파일, 비밀정보 검사, `git diff --check`, Pages 빌드도 통과했다. 사진·보드·폼 관련 자동 검증은 합계 37개다.
