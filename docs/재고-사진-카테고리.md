# 재고 관리 · 2026-10-05

품목은 이름으로 등록하며 카테고리별 텍스트 목록으로 표시한다. 드래그하거나 이동 버튼을 눌러 카테고리를 바꾼다.

## 화면과 동작

- 사진·보관 위치 입력과 표시, 위치 검색·이동은 사용하지 않는다.
- 등록·수정 폼에 이름·단위·현재 수량을 표시한다. 병은 미개봉 수량과 한 병 용량을 입력하며, 개봉 병 잔량은 유지한다. 부족 알림 기준과 메모는 접힌 추가 설정에 둔다.
- 목록과 상세 화면에서 품목을 삭제할 수 있다. 삭제 확인 후 목록에서 제외하며, 수량이 남아 있어도 삭제할 수 있다.
- 삭제된 품목의 원본 수량·개봉 병·입출고 이력은 보존한다. 삭제 이후 수정·수량 기록·카테고리 이동은 차단한다.
- 재고 기록에서 행사 조회·연결 입력·저장을 제거했다. 행사 준비 화면에서도 재고 연결 안내와 바로가기를 제거했다.
- 카테고리 생성·수정·빈 카테고리 삭제, 검색, 변경 이력을 유지한다.

## 목록 배치 개선

카테고리 탐색과 카테고리별 품목 목록을 분리한다. 데스크톱은 왼쪽에서 카테고리를 선택하고, 좁은 화면은 위쪽 버튼으로 선택한다. 카테고리는 위에서 아래로 이어지며, 각 카테고리 안의 품목은 가용 폭에 따라 여러 열로 배치한다. 품목명 바로 아래에 잔여량과 작업 버튼을 둬 개별 품목의 정보를 가깝게 모은다.

카테고리 선택과 이름 검색을 함께 적용하며 선택 상태는 재조회 후에도 유지한다. 전체 보기에서 비어 있는 카테고리의 큰 빈 영역을 숨기고, 카테고리 선택 영역에는 계속 남겨 등록·수정·이동에 사용할 수 있게 한다. 품목을 카테고리 버튼이나 목록으로 드래그해 옮길 수 있고, 이동 버튼으로도 같은 작업을 한다. 삭제 X는 각 행 우상단의 배경 없는 버튼으로 유지한다.

페이지 전체의 고정 폭 제한은 두지 않는다. 품목 그리드는 최소 340px과 16px 간격을 기준으로 일반 데스크톱에서 2열, 넓은 데스크톱에서 3열, 좁은 화면에서 1열로 바뀐다. auto-fill을 사용해 품목이 적거나 검색 결과가 적을 때도 품목 폭이 지나치게 늘어나지 않게 한다. 긴 이름은 줄바꿈하고, 삭제 X의 우상단 공간과 아래쪽 수량·버튼 정렬을 유지한다.

이 배치 변경은 클라이언트와 관련 테스트만 수정한다. 저장된 품목·수량·분류 및 서버 API는 바꾸지 않으며, Functions 재배포는 필요 없다.

## 변경 영향과 호환성

변경 소스는 `web/src/inventory.js`, `inventory.css`, `admin.js`, `admin-forms.js`, `inventory-forms.js`와 `functions/src/domain.js`, `service.js`, `deletion.js`다. 관련 테스트·문서·공개 빌드 파일도 갱신한다.

구형 클라이언트의 재고 요청에 포함된 `eventId`는 입력 호환을 위해 받아 버린다. 행사 존재 여부를 조회하지 않으며 새 재고 이력에 행사 연결을 저장하지 않는다. 다른 행사·정산 API는 변경하지 않는다.

삭제는 기존 소프트 삭제 방식이며 확인·권한·수정 버전·중복 요청 검사를 유지한다. 수량이 남은 품목도 목록에서 사라지는 것이 변경점이다. 실제 운영 품목 삭제나 데이터 일괄 수정·이관은 배포 과정에서 수행하지 않는다. 기존 사진·위치·행사 연결 자료는 일괄 삭제하지 않는다.

## 현재 수량 입력 수정

기존 품목 폼의 “수량 설정”은 실제 수량 없이 용량·최소 보유량만 저장했다. 사용자가 재고로 입력한 값이 부족 알림 기준에 남아 현재 수량은 0으로 표시될 수 있었다.

`saveItem`은 선택적 `quantity`를 받아 품목과 수량 실사 이력을 같은 트랜잭션에서 저장한다. 생략하면 기존 수량을 유지하며, 신규 0·동일 수량은 불필요한 이력을 만들지 않는다. 병·개·팩은 정수, mL·g은 소수를 허용하고 0–100,000 범위를 검사한다. 기존 권한·수정 버전·삭제 보호와 재고가 남은 품목의 단위·용량 변경 제한은 유지한다.

품목 수정의 현재 수량은 기존 수량을 교체한다. 입고처럼 누적하지 않는다. 최소 보유량을 실제 재고로 자동 추정하거나 일괄 변환하지 않는다. 별도 복구가 필요한 데이터는 대상·변경 전후 값을 확인하고 명시적 승인 뒤 조건부 원자적 갱신으로 처리하며 이력을 남긴다.

## 검증과 배포

재고 렌더러와 폼 테스트, 로컬 Firestore 통합 테스트로 재고 전용 권한, 행사 접근 없음, 저장 필드, 수량이 남은 품목 삭제, 이력 보존 및 삭제 후 변경 차단을 검증한다. 비밀정보 검사·문법 검사·빌드도 수행한다.

서버 함수를 먼저 배포해 품목과 현재 수량의 동시 저장을 지원한 뒤, main의 GitHub Pages와 Firebase Hosting에 클라이언트를 배포한다. 보안 규칙·IAM·키·과금·도메인 설정 변경과 운영 데이터 마이그레이션은 필요하지 않다. 코드 배포는 기존 승인 범위 안의 작업이며, 데이터 복구는 별도 승인 범위만 적용한다.

지정된 Browser/Chrome 확장 연결이 없어 실제 브라우저 화면과 터치 조작은 확인하지 못했다.
