# 관리인원 공통 금액과 체크박스

행사 상세의 신청 · 출석 화면 위에서 관리인원 공통 금액을 한 번 설정한다. 0원도 사용할 수 있다. 신청자 목록이나 신청 처리 창의 관리인원 체크박스를 선택하면 바로 저장하며, 체크를 해제하면 해당 신청에 저장된 원래 참가비로 돌아간다.

공통 금액 변경은 같은 행사에서 참가 등록·대기·승급 제안 중인 기존 관리인원에게 함께 적용한다. 다른 행사, 일반 참가자, 취소·만료·삭제·익명화 신청은 변경하지 않는다. 확인된 입금액보다 낮아지는 사람이 있으면 전체 변경을 거절한다. 화면에서 정산 권한이 있는 임원이 실행할 때만 적용하며 배포 중 기존 운영 자료를 일괄 변경하지 않는다.

[2] 키·권한: 비밀 검사에서 개인 자격증명 패턴 0건. .env.local, serviceAccount.json, .secrets 없음. 추적된 환경 파일은 안전한 .env.example뿐이다. 기존 CLI 인증을 사용하고 비밀 값을 출력·커밋하지 않는다. 재무 권한, Firestore/Storage 직접 접근 차단, 공개 응답의 내부 금액 필드 제외를 유지한다.

[3] 변경: 행사별 공통 금액, 기존 관리인원 일괄 적용, 목록·처리 창 체크박스, 체크 해제 시 원래 금액 복원, 실패 시 체크 복원, 금액·지정 버전 충돌 검증, 구형 클라이언트 호환.

[4] 파일: functions/src/staff-pricing.js와 service.js, web/src/staff-pricing.js와 admin.js·admin-forms.js·main.js·style.css, tests/staff-pricing.test.mjs와 tests/browser/staff-pricing.spec.js, package.json, SECURITY.md, 이 문서와 Pages 빌드 산출물.

[5] 위험: High — 승인된 서버 배포와 main 반영, 사용자가 공통 금액을 적용할 때 관리인원 청구액 일괄 수정. 트랜잭션으로 전체 성공 또는 전체 취소하며 입금 상한을 검사한다. Medium — 서버 선배포가 필요하다. 구형 클라이언트는 공통 금액 설정 전까지만 기존 개인별 금액 지정을 허용하고, 설정 이후 다른 금액 입력은 거절한다. Low — 최대 498명의 관리인원을 한 트랜잭션에서 적용한다. 초과 시 아무 데이터도 바꾸지 않고 명시적인 오류를 반환한다.

[6] 검증: 단위 11개, 기존 통합 56개, 카테고리 서버 11개, 관리인원 서버 9개, 데스크톱·모바일 16개로 총 103개 통과. 서버는 독립된 로컬 Firestore 에뮬레이터 프로젝트에서, 브라우저는 API 모의 응답으로 검증했다. 공통 금액 적용·입금 상한·동시 변경·권한·공개 노출 방지·체크 복원·환불·기존 기능을 확인했다. 화면 캡처 확인과 모바일 가로 넘침 검사도 완료했다.

[7] 수행하지 않은 작업: 운영 데이터에 임의 금액 입력 또는 관리인원 지정, 운영 장부·명부 일괄 변경, 실제 입금·송금·환불, 보안 규칙·IAM·키·과금·도메인 변경, force push. 기존 Artifact Registry 이미지 정리 정책도 변경하지 않는다.

[8] 사용자 조치: 행사 상세 → 신청 · 출석 → 관리인원 금액 설정 후 대상자의 체크박스를 선택한다. 금액을 지정하지 않은 행사에서는 새 관리인원 체크가 비활성화된다. 이전에 지정한 관리인원은 첫 공통 금액 적용 전까지 기존 금액을 유지한다.
