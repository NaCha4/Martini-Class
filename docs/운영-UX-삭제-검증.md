## [2] 비밀 정보와 권한 점검

`npm run check:secrets` 통과. 검사 대상 소스에서 개인 키·서비스 계정 서명을 발견하지 않았고 `.env.local`, `serviceAccount.json`, `.secrets`는 없었다. 민감 파일 패턴의 Git 추적 결과는 안전한 예제인 `.env.example`만 해당한다. 공개 Firebase 설정은 기존 값을 유지한다. IAM, 로그인, API 키, Security Rules, 과금 설정은 변경하지 않았다.

삭제 요청은 서버가 기존 업무 권한을 확인하고 허용된 자료 종류만 받는다. 확인 값, 수정 시각과 버전을 검증한다. 확정 회의록은 기존 정정 권한과 동일하게 회장단 권한이 필요하다.

## [3] 변경 내용

- 운영 메뉴를 활동 운영 / 운영 지원 / 관리·설정으로 분류하고 업무 키워드로 메뉴를 검색한다.
- 운영 홈에 주요 업무 바로가기를 제공한다.
- 행사 전체 목록을 불러와 다가오는 활동, 초안, 지난 활동 순으로 정렬한다. 상태·유형·검색을 함께 적용하고 뒤로 가기 시 복원한다.
- 행사 카드에 담당, 학기, 신청 마감, 대기 인원과 참가자 관리 동선을 표시한다.
- 행사 작성 화면을 기본 정보 / 일정 / 정원·참가비 / 모집 상태로 나눈다. 선택 질문은 접어둔다.
- 신청 화면의 ‘신청서로 이동’은 개인 접근 값이 들어 있는 URL을 변경하지 않고 입력란으로 이동한다.
- 실제 입출금 장부를 기본으로 펼쳐 저장한 기록과 삭제 버튼을 바로 확인하게 한다.
- 행사, 참가 신청, 재고 품목, 회의록, 결정·할 일, 게시글, 입출금 기록에 X 버튼을 추가한다. 부원·지출 계획·역할·임원은 기존 X 기능을 유지한다.

### 삭제의 의미와 연결 자료

새 삭제 기능은 목록에서 제외하고 원본·삭제자·삭제 시각을 보관하는 방식이다. 공개 게시글은 비공개 처리하고 삭제된 행사·신청의 접근 링크를 차단한다. 개인정보 영구 정리는 기존 학기말 정보 정리 절차를 사용한다.

- 행사: 초안·취소·완료 상태에서만 삭제한다. 진행 중 신청, 대기·승급 예약, 미납·미환불이 남으면 먼저 정리하도록 안내한다.
- 참가 신청: 취소·만료 후 미환불이 없을 때 삭제한다. 기존 재신청 시 이력 보관을 유지한다.
- 장부: 잔액 계산에서 제외한다. 납부·환불 합계, 회비 거래 연결, 지출 계획 집행 상태를 같은 트랜잭션에서 정정한다. 이미 환불한 납부 기록은 환불 기록을 먼저 정정해야 한다. 실제 은행 거래는 실행하지 않는다.
- 재고: 수량을 먼저 정리한 품목만 삭제하며 입출고 이력은 보관한다.
- 회의: 살아 있는 결정·할 일 연결을 먼저 해제해야 한다.
- 원본을 보관하므로 삭제한 동일 거래 요청을 재전송해도 중복 반영되지 않는다.
- 감사 로그, 입출고 이력, 수정 이력과 필수 운영 설정에는 일반 삭제 버튼을 제공하지 않는다. 추적 근거를 유지하기 위한 구분이다.
